# PR spec: 개발 하네스와 공통 LLM wiki

## 목적
LLM 종류와 무관하게 같은 프로젝트 지식을 읽고, 각 PR 개발 전에 spec을 기록하며 작은 범위로 개발한다.

## 범위
- 첨부 Markdown 7개를 docs/references에 원문 보관하고 요구사항 정리는 보류한다.
- docs/wiki에 공통 진입점, 개발 규칙, 현행 상태와 변경 기록을 둔다.
- AGENTS.md, CLAUDE.md, GEMINI.md에서 공통 문서를 안내한다.
- Claude/Codex 공식 지침을 조사하여 저장소 공통 지침을 간결하게 구성하고, 실제 빌드의 기술 스택과 상세 문서의 조건부 읽기를 명시한다.
- PR당 docs/spec/yyyy-mm-dd-slug.md 한 개를 첫 독립 커밋으로 작성하는 규칙과 Git 이력 검증을 제공한다.
- PR 크기, spec 순서/내용, wiki 갱신을 로컬 명령으로 검사한다.
- README에 프로젝트의 SDD 적용 방식, 현재 기술 스택, 설계·검증 방법론을 소개하고 상세 실행 절차는 wiki로 연결한다.

## 제외
제품/시스템 요구사항 재구성, 애플리케이션 기능 변경, 외부 서비스 연동, 원격 PR 생성 및 병합, GitHub Actions workflow와 브랜치 보호 설정.

## 변경 경로
- docs/**
- AGENTS.md
- CLAUDE.md
- GEMINI.md
- README.md
- scripts/**
- .github/pull_request_template.md

## 인수 조건
- 첨부 원문이 바이트 단위로 보존된다.
- 루트 지침에는 현재 기술 스택, 핵심 개발 계약, 관련 문서 진입점만 두고 전체 wiki/원문의 일괄 읽기를 요구하지 않는다.
- Claude는 공식 @ import로 공통 AGENTS.md를 재사용한다. 조사 근거는 wiki에 남긴다.
- 최초 커밋은 새 spec 한 개만 포함한다. 후속 커밋에서 같은 spec에 결과를 보충할 수 있다.
- spec 없는 변경, 구현과 동시에 작성한 spec, 여러 spec, wiki 검토 누락 및 크기 초과는 실패한다.
- 기본 PR 한도는 원문 보관 경로를 제외한 25개 파일 및 추가+삭제 800줄이며 20개/600줄부터 분할 경고한다.
- 새 원문 보관은 docs/references 하위 Markdown만 별도 한도 10개/5000줄로 검사한다.
- 범위가 커지면 개발을 멈추고 후속 PR로 분리한다. 독립 목표는 크기와 무관하게 분리한다.

## 검증
Python 표준 라이브러리 unittest로 임시 Git 저장소에서 정상/실패 사례를 검사한다. 실제 작업 diff도 검사하며 원문 해시를 비교한다.

## Wiki 영향
개발 규칙과 현재 저장소 상태를 신규 문서화한다. 제품 요구사항은 미정리 상태로 명시한다. 매 PR wiki 변경 기록에 요구사항 변경 여부와 근거를 남긴다.

## 분할 계획
이번 PR은 하네스 설치만 포함한다. 요구사항 정리와 각 도메인 구현은 각각 후속 PR spec으로 시작한다.

## 결과
개발 전 spec을 독립 커밋으로 작성했다. 구현 후 Git 임시 저장소 회귀 테스트 15개, 실제 작업 diff 검사, 원문 7개 바이트 일치 및 공통 지침/wiki 링크 검증을 완료했다. 하네스는 공통 LLM 지침과 로컬 검사로 운영한다.

## 변경 이력
- 사용자의 추가 요청에 따라 날짜형 spec 경로를 docs/spec/으로 조정했다. 최초 spec 커밋을 경로에 맞춰 갱신한다.
- 사용자의 추가 요청에 따라 GitHub Actions workflow를 제거하고 공통 LLM 지침과 로컬 검사만 유지한다. 브랜치 보호 설정도 작업 범위에서 제외한다.
- 공식 문서 기반의 지침 개선 요청을 같은 하네스 PR 범위에 추가했다. 지침 수정 전에 이 spec에 반영했으며, 기술 스택은 빌드 선언과 도입 계획을 구분한다.
- 지침 개선 검증: 공통 지침/wiki 상대 링크와 Claude import 대상, 스택 버전의 빌드 선언 일치, 로컬 PR 검사 통과를 확인했다. 문서만 변경하여 앱 테스트는 실행하지 않았다.
- README 개선 요청을 반영하기 전에 범위를 기록했다. 개발 시작 안내와 작업 템플릿을 프로젝트 방법론 소개로 바꾸고, 기존 설계 원칙과 실제 도입 상태를 구분한다.
- README 검증: 구성·상대 링크·빌드 버전 일치와 로컬 PR 검사 통과. 일반 변경이 600줄 경고 기준에 도달하여 이번 하네스의 내용 확장은 여기서 마치고 추가 개선은 후속 PR로 분리한다.
